# Cerea UI review before onboarding new users (2026-11-07)

Independent product-design review of Cerea main `b9ebcd92` + Pystino `ce1b73b` (v0.29.0), from the screenshot sweep in `screenshots/2026-11-07-uireview/` (368 files, light/dark, 1440/390; see `index.md` there). Every screen was looked at in light 1440 and light 390; dark was sampled across all areas. File names below are relative to that folder, without the `-light-1440.png` suffix unless a specific variant matters.

## 1. Verdict

1. The bones are good: a calm two-pane layout, a sensible sidebar (Chats | Agents, projects, schedules, workspace), honest copy about cost and mistakes, solid light/dark parity, and a mobile layout that mostly holds. This is closer to Claude/ChatGPT quality than most self-hosted chat UIs.
2. The first hour is not ready: a new user signs in on a stock Authelia page with no Cerea on it, lands on a blank screen with a Piedmontese word they cannot read, and has nothing telling them what Cerea can do, where projects are, or what "Asks first" means.
3. Too many raw internals reach users: model ids, `0E-12 cost per month exceeded`, `waiting-permission`, JSON tool arguments, model tokens leaking into chat titles, curl/`--issuer` commands, `fake-embed`, git hashes.
4. Vocabulary drifts on nearly every screen (chats/conversations, device/machine/computer, agent/session/task, Plan·Build vs Plan·Ask·Auto·Allow, person/people vs users), and the error and quota paths are broken (a link to a Settings tab that does not exist).
5. Agents mode has the right ideas (the "need you" inbox, the policy in plain words, diffs) but it talks to developers; the pairing dialog and approval cards are the biggest trust gap for the audience you are onboarding.

## 3. Proposals

### Quick wins (≤ half a day each)

1. **Brand the sign-in page.** Why: it is the first screen of the product and currently belongs to Authelia. Shots: `signin-authelia-*`, `signin-console-*`. Proposal: Authelia asset override with the ridge logo + "Cerea" above "Sign in", button "Sign in" in sentence case and the app's blue, drop "Powered by Authelia" to the footer, dark theme = system.
2. **First-run greeting.** Why: "Va bin", "Com'è?", "Fuma c'anduma", "Facciamo che iniziare?" rotate randomly; a non-Piedmontese user sees an unknown word and no name. Shots: `empty-chat-first-screen-*`, `chat-new-empty-*`, `logo-ab-*`. Proposal: on the first three visits show the ridge + "Cerea" with the subline "That's hello in Piedmontese. Ask me anything, or try one of these." Keep the rotating greetings afterwards as the delight they are, but always with a 12 px English subline ("hello" / "how's it going?" / "shall we start?").
3. **Starter chips on the empty chat.** Why: a blank page is the weakest onboarding state; Claude and ChatGPT both seed 3–4 prompts. Shots: `empty-chat-first-screen-*`. Proposal: four chips under the composer: "Summarise a document (drop a file)", "Search the web for today's news about…", "Make a table comparing…", "Draft an email to…"; admins can edit them under Admin → Assistant.
4. **Explain "Asks first".** Why: the pill in the composer is the permission mode for tools and nobody will guess that. Shots: `chat-new-empty-*`. Proposal: label "Asks before using tools"; tooltip "Cerea asks you before it uses a connector or runs code. Switch off to let it act on its own in this chat."
5. **One word for one thing.** Shots: `project-conversations-*`, `projects-list-*`, `empty-sidebar-agents-*`, `agents-pair-dialog-*`, `agents-new-session-*`. Proposal: chats (never conversations); computer (never device/machine); agent session → "session" in the UI, "New session", "Start session"; drop "Posture: Plan/Build" for the same Plan/Ask/Auto/Allow steps used in the session; "users" (never person/people) in all admin copy.
6. **Readable approval cards in chat.** Shots: `chat-approval-card-*`. Proposal: title "Team notes wants to search your notes for 'release'", a "Show details" disclosure for the JSON, explain the timer ("Waiting 25 min, then it is refused"), make Deny a real outlined button.
7. **Sanitise auto titles** (see bugs). Half a day, high visibility.
8. **Label icon-only controls.** Shots: `agents-session-waiting-*`, `agents-session-waiting-390`, `sidebar-agents-*`. Proposal: Stop square → "Stop" with text at ≥ 768 px and aria-label below; the 9 % ring → "Context 9 %" with the tooltip "How full this session's memory is"; the amber "?" badge in the sidebar → tooltip "Waiting for you".
9. **Move developer strings out of Settings and the console Overview** (API base URL, build hashes, `.env`, `./configure`) into collapsed About/How-it-works rows. Shots: `settings-application-*`, `console-dashboard-*`, `console-settings-*`, `console-search-*`.
10. **Fix the small copy slips**: the two grammar errors in admin, "0.44.0· b9ebcd9", "1 needs you", the chat-schedule subtitle, the "Custom models tab" tip, "within 0s", the dangling "—" separators in the review log at 390.

### Medium (1–3 days)

1. **Usage and allowance surfaced in Cerea.** Why: self-hosted means someone pays; users near a limit get a broken path today. Shots: `error-quota-exceeded-*`, `settings-usage-grace-*`, `sidebar-user-menu-grace-*`. Proposal: a Settings → Usage tab (this month's spend, allowance bar, reset date, by model, by project), the user-menu meter, and the quota error rewritten and linked to it. Deliberately differ from Claude/ChatGPT here: show money, not "message limits".
2. **Chat message presentation.** Why: assistant replies sit in a bordered card with "Thinking ›" / "Used 1 tool ›" as the first line, and copy/retry icons far right under the card; it reads as a log, not a conversation. Shots: `chat-web-search-*`, `chat-project-chat-*`, `chat-docx-*`. Proposal: borderless assistant text with a small ridge avatar, tool/thinking steps collapsed into one grey line at the end ("Searched the web · Thought for 4 s"), actions on hover under the text, a sources row for citations and for knowledge-base hits ("Source: runbook-incident.md" becomes a chip that opens the document).
3. **Model picker with meaning.** Shots: `chat-model-picker-*`, `agents-model-effort-*`. Proposal: each row gets a one-line description and a cost cue ("GPT-OSS 120B · default · balanced · €"), the admin's description text comes from the console model entry; show "Why pick this?" tooltips rather than ids.
4. **New project form.** Shots: `projects-new-*`, `project-settings-*`. Proposal: two steps: Name + What it is for + Instructions (create), then the optional sections on the project's Settings tab. Replace "1 · in full" / "4 · searched" badges with the two headings only ("Read in full on every message" / "Searched when relevant") and keep the excellent cost note. Sticky Create button.
5. **Workspace page density.** Shots: `workspace-*`. Proposal: drop the duplicate H1 (page says "Workspace", card says "Models"), make the blue summary strip a single line, move Quick tips into a "?" popover next to the tab name, show model ids only in Edit, replace per-row red Delete buttons in Memory with a "…" menu.
6. **Mobile fixes for Agents and the console** (see bugs): labelled mode selector at 390, sticky footers in sheets, wrapping diff lines or scroll shadows, card rows for console tables.
7. **Agents empty state.** Why: in Agents mode with no computer paired, the main pane shows the ordinary chat composer and a dialect greeting; nothing says what an agent is. Shots: `empty-sidebar-agents-*`. Proposal: replace the main pane with a three-step card: "1 Connect a computer · 2 Pick a folder · 3 Tell the agent what to do. It asks before it changes anything." with one "Connect a computer" button; disable "New session" until a computer is online.
8. **Approval cards with risk language in Agents.** Shots: `agents-needs-you-*`, `agents-session-waiting-*`, `agents-auto-reviewer-*`. Proposal: title in plain words ("Run the project's tests", "Delete the folder .pytest_cache", "Download and run a script from example.com"), a risk tag (Reads · Changes files · Deletes · Internet), raw command under "Details", "Always allow (this session)" demoted to a text link and confirmed for Deletes/Internet, and the reviewer's reason as the subtitle in Auto.
9. **Console vocabulary pass.** Shots: `console-*`. Proposal: nav "Summary → Home", page "Reports → Usage", "Quotas/Quota usage → Limits (rules + who is near theirs)", "Routing → Model names", "SERVING/DEPLOYMENT/PRIVACY → Models & access / People / Money / System", audit codes mapped to sentences ("Added a model"), "kind mismatch" explained with a Fix link, a "Back to Cerea" link in the header.

### Bold ideas

1. **A guided first hour.** Why: today the product assumes a user who already knows what projects, knowledge bases, connectors and agents are. Proposal: a dismissible 4-card welcome on the empty chat (Ask · Add a file or project · Search the web · Let it work on your computer), and the first three replies end with one contextual nudge ("Want Cerea to remember this? Turn on Memory in Workspace."). Progress saved per user; admins can turn it off.
2. **Agents as "a helper on your computer" with a trust rail.** Why: Plan/Ask/Auto/Allow, shield sheets and JSON are the correct controls for developers and opaque for everyone else. Proposal: a persistent strip at the top of every session: folder boundary ("Working only in shop-api"), mode in a sentence ("Asks before changing anything"), what it is doing now ("Editing cart.py"), cost so far, and one labelled Stop button. The shield sheet becomes four radio cards with "what it does on its own / what it asks" columns and an "Always allowed" list with Remove buttons. First session always starts in Plan with a banner offering to step up. Changes pane gets "Undo all" and per-file Undo.
3. **Connect-a-computer wizard.** Why: a `curl … --issuer … --gateway … --default-group` block is where non-technical users stop. Proposal: OS tabs (Mac/Windows/Linux), one copy-paste line, live three-step progress (Installed → Signed in → Connected) that ticks as the helper checks in, then "Which folder may it work in?" and a sample first task. Options collapse under Advanced; "Use a project's own opencode setup" moves there with the wording "Let projects add their own commands (only for projects you trust)".
4. **Day-one admin in Cerea, not the console.** Why: a parent or office manager must today find Providers, Models, Groups ("Models: none granted" blocks everyone), Quotas and Users across 15 console pages under a "Pystino LLM gateway" brand with no way back. Proposal: Cerea Admin gets a "Set up" checklist: paste a provider key → tick the models to offer (price pre-filled) → invite users and pick their group → set one monthly limit. The console remains for advanced items (aliases, redaction, reconcile, audit, identity providers) and gets the Cerea shell. The chat user menu then shows "Admin" and "Advanced (gateway console) ↗".
5. **Make cost a feature.** Why: Claude and ChatGPT hide cost; Cerea runs on the user's own money and already writes honest lines ("These add to the cost of every reply", "the reviewer is billed to you"). Proposal: a cost chip per reply on hover ("€0.0004 · 1.2k tokens"), a per-project monthly figure on the project card, and the allowance meter in the user menu. This is the one place Cerea should deliberately differ from the consumer apps.
6. **A design-token pass for consistency.** Why: three Save styles, black vs blue primary buttons (Allow once is black, New chat is blue), blue summary strips on every list page, 12–13 px helper text everywhere, native selects at 24 px. Proposal: one primary (accent) button, one secondary, one destructive-in-menu; summary strips become a single stat line; body 15 px / helper 13 px / min target 40 px; icon buttons always get aria-labels and visible focus rings (not verifiable in screenshots, so test with keyboard before launch).

## 4. Top 10 by impact on getting new users on board

1. Brand and theme the sign-in page (Authelia): logo, "Sign in to Cerea", sentence case, dark mode.
2. First screen: welcome + English subline under the Piedmontese greeting + four starter chips + a visible "New project" (the grey "+" at sidebar level is not discoverable).
3. Fix the quota/error path end to end: plain message, no `0E-12`, no empty bubble, no extra chats per retry, a Usage tab that exists, an allowance meter in the user menu, and a notice when a chat's model is gone.
4. Remove raw internals from user-facing surfaces: auto-title sanitising, model ids, `waiting-permission`, JSON approvals, `fake-embed`, build hashes, API URL.
5. One vocabulary: chats, computer, session, Plan/Ask/Auto/Allow everywhere, users.
6. Plain-language approval cards with risk tags (chat connectors and Agents), Deny as a real button, timer explained.
7. Agents first run: empty-state explainer + Connect-a-computer wizard with Advanced collapsed.
8. Mobile: table artifacts overflow, unlabelled mode icons and "s…" titles at 390, sheets without Done, console tables.
9. Trust rail in agent sessions: mode sentence, folder boundary, cost so far, labelled Stop, Undo in Changes.
10. Day-one admin checklist inside Cerea Admin; de-jargon the console and give it a way back.

## 5. Logo verdict

**Use A (thin vector ridge).** Shots: `logo-ab-A-*` vs `logo-ab-B-*`.

- At sidebar size (about 80 × 30 px) B's stair-stepped pixel line reads as aliasing, a jagged rendering glitch rather than a drawing, and on dark (`logo-ab-B-dark-390`) the steps catch the eye more than the chat list does. A reads as a mountain ridge instantly and stays quiet.
- A is the same drawing as the large hero mark on the empty chat, so the small and large marks agree; B would make the sidebar and the hero look like two brands.
- Two fixes for A: thicken the stroke about 15 % at the small size (optical compensation; today it is lighter than the "Chats | Agents" labels), and put the word "Cerea" next to it in the sidebar. Right now the product's name appears nowhere in the chrome, which is part of why the random greeting is confusing.
- B's pixel idea is worth keeping only at 16–32 px as the favicon/PWA icon, where a thin vector line smears and a pixel grid is crisp.
