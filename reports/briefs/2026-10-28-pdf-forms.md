# Brief: fill uploaded PDF forms reliably (Cerea #39, steps 1 and 2; next release)

Read issue #39 first: `gh issue view 39 -R paoloviviani/Cerea`. Step 3 (forms without fields) is out of scope: it depends on #38, which is parked.

## Context
- Uploads keep the original PDF bytes beside the extracted text (`src/lib/server/files/uploadFile.ts`). The sandbox reads it at `/mnt/data/<name>`, and the document tools get files through the conversation's file store.
- Today the only route is the `pdf-tools` skill in the sandbox (`src/lib/server/skills/builtin/pdf-tools/scripts/pdf_tools.py`, pypdf), which has four bugs:
  1. `fill_form` fills page 1 only (`writer.pages[0]`);
  2. `form_fields` filters on `/CheckBox`, `/RadioButton` and `/Choice`, which aren't PDF field types (the real ones are `/Btn` and `/Ch`), so checkboxes, radios and lists are never listed;
  3. `flatten=True` calls `page.flatten()`, which pypdf doesn't have. In pypdf 6.x, flattening is the `flatten=` argument of `PdfWriter.update_page_form_field_values`;
  4. allowed values (a checkbox's on-state, a radio group's options, list items) aren't exposed.
- `cerea-documents` (Python, `documents/`) already depends on `pypdf>=5`. Its `doc_outline`, `doc_read` and `doc_edit` cover docx, xlsx and pptx; PDF has create only.

## Step 1: fix the skill helper (sandbox route)
- `form_fields(path)` returns, per field: the full name, the type (text, checkbox, radio, list or combo, signature), the page number(s), the current value, the allowed values (for a checkbox its on-state name(s); for a radio group the options; for `/Ch` the options as display and export), required/read-only flags and max length when set.
- `fill_form(path, values, out_path, flatten=False)`:
  - fills every page (`page=None`, or per page where needed);
  - accepts `True`/`False` or the on-state name for checkboxes, and an option for radios and lists;
  - validates every value and raises a clear error naming the field and its allowed values;
  - generates appearances (`auto_regenerate` / NeedAppearances as pypdf supports) so viewers show the values;
  - flattens through the supported argument;
  - afterwards re-reads the output and returns a report: filled, skipped, rejected.
- Update the skill text: always call `form_fields` first; map the user's data to field names and ask about anything ambiguous; report what was filled. Detect XFA (`/XFA` in the AcroForm) and say it can't be filled here.
- Test it in the sandbox environment the skill uses (Pyodide's pypdf version may differ from CPython's; check which version the sandbox loads and test against it, or keep the helper compatible with both).

## Step 2: PDF forms in the document tools (server, preferred route)
- `doc_outline` on a PDF returns its pages (count, size) and, when it has an AcroForm, its fields as in step 1 (name, type, page, options, value, flags). XFA is reported as such.
- `doc_edit` on a PDF gets one operation, `fill_form({values, flatten?})`:
  - it applies the same validation as step 1 and generates appearance streams so every viewer shows the values;
  - it saves a new version under the same name, like the other `doc_edit` operations;
  - the verification report re-reads every value and lists any that didn't take.
- PDF has no other edit operations; say so in the tool description.
- Follow the service's existing structure: the op registry and schemas (`schemas.py` / `spec.py` `friendly` errors), the limits, `zipsafe`/size checks where they apply to PDF, and the capability fixture (`src/lib/server/documents/capabilities.fixture.json`, regenerated with the command in `documentsContract.spec.ts`). Keep the tool description within its budget.
- The PDF skill (`builtin/pdf/SKILL.md`) and `pdf-tools`: when `doc_edit` is available, PDF forms go through `doc_outline` + `doc_edit fill_form`; the sandbox helper is the fallback only. One clear rule, no competing instructions (the same principle as the Office skills).
- Docs: `docs/office.md` (or wherever the document tools are described) gets a short "Filling PDF forms" section. Say "users", not "people", in new text.
