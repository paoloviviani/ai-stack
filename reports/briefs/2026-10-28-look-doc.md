# Brief: look_doc, the model sees pages of documents (Cerea #38, next release)

Read issue #38 first (`gh issue view 38 -R paoloviviani/Cerea`); the owner unparked it on 2026-10-28. Remove the `parked` label when you open the branch (`gh issue edit 38 --remove-label parked`).

## Goal
A built-in tool, `look_doc({file, pages?})`, returns images of chosen pages or slides of a Word, Excel, PowerPoint or PDF file in the conversation (an upload or a file the assistant made), so a model with vision can check the layout of what it produced, or read a form or a scanned page as it really looks.

## Pipeline (decided)
1. **Office files to PDF:** reuse the chat's preview pipeline (`src/lib/server/office/gotenberg.ts`, `previewStore.ts`, cached by content hash). A file already previewed costs nothing. PDFs skip this step.
2. **PDF pages to PNG in `cerea-documents`, with `pypdfium2`** (Apache-2.0 / BSD-3; PDFium is BSD-3). Not PyMuPDF (AGPL).
   - A new endpoint, e.g. `POST /render` with the PDF bytes, the page list and a target size, returns the PNGs and the page count.
   - Same auth (shared secret), limits and memory cap as the other endpoints. Load pypdfium2 lazily, only for render jobs: the 150 MiB worker cap already bit pypdf.
   - Add pypdfium2 as a runtime dependency. `documents/tests/test_licences.py` must still pass (OSI classifiers; extend its allow-list only with a justified entry).
3. **The tool** (chat server, `src/lib/server/textGeneration/builtinTools/`):
   - resolves the file by name through the conversation's files (as the doc_* tools do);
   - gets the PDF (preview or original), calls render, and returns the images as image content in the tool result for the model.

   Find how tool results carry images today (`mcp/fileRefs.ts` and the tool-result plumbing in runMcpFlow) and reuse it; don't invent a parallel path.

## Behaviour
- **Pages:** 1-based numbers or ranges. The default is the first pages up to the cap; a deck's default is the slides the last doc_edit touched if that's easy to know, otherwise the first ones. Cap **6 images per call**, and say how many pages exist, so the model can ask for others.
- **Size:** longest side about 1,200 px for slides, about 1,000 px wide for pages. Use JPEG or PNG, whichever is smaller for typical content; state which. Report the approximate token cost in the tool description so the model is sparing.
- **Offered only when it can work:**
  - the conversation's model accepts images (`multimodal` / input modalities in `models.ts`);
  - the documents service is configured, and for Office files Gotenberg is too.

  Otherwise the tool is absent (not an error at call time).
- **Errors are plain:** unknown file, a format that can't be rendered, conversion failed, encrypted PDF, too many pages requested.
- **Fidelity note in the description:** Office files are rendered by LibreOffice, so fonts and line breaks can differ slightly from Microsoft Office. It's good for spotting broken layouts, not for pixel checks.
- **Skills:** the PowerPoint, Word and PDF skills get one line on when to look. After creating or redesigning a deck or document, and after an edit that changes layout, look at the affected pages once and fix what's broken. Not after every small text edit. Reading a scanned or image-only PDF is also a good use. Keep "no PDF just to preview" (0.32.1) intact: look_doc is for the model, the preview is for the user.

## Not in scope

- Filling PDFs that have no form fields (#39 step 3); that comes after this.

## Tests (each fails without its fix)
- **Service:**
  - render a known PDF: page count, image size, page selection, the cap;
  - an encrypted PDF is refused;
  - the memory cap holds (a render on a big page);
  - pypdfium2 isn't imported by `cerea_documents.core`.
- **Chat:**
  - the tool is absent for a text-only model and present for a vision model;
  - it resolves a pptx through the preview cache, calling Gotenberg once for two calls (mock Gotenberg and the service);
  - the images reach the model's next request as image content;
  - the page cap and page-range parsing work, with clear errors.
- **One real end-to-end check:**
  - build a deck with doc_create containing a deliberately overflowing text box;
  - render it through Gotenberg 8.38.1 (under the heavy lock, 127.0.0.1, container removed) and the real service;
  - look at the PNG yourself: the overflow must be visible;
  - save it in `/home/ubuntu/workspace/ai-stack/reports/screenshots/2026-10-28-look-doc/`.
