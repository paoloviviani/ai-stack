# ADR 0110: goose as an officially supported engine (opt-in, beside opencode)

- Status: accepted (owner, 2026-11-06)
- Builds on: ADR 0108 (engine-independent diffs, history, gateway cost, connectors; ACP spike PR #122),
  ADR 0109 (no machine limits; session words; fixed floor).

## Decision

A machine can run **goose** instead of opencode, chosen at enrollment, through galopin's ACP backend
(`goose acp`). opencode stays the default. "Supported" means: installed and pinned by galopin, configured by
galopin, covered by CI against the pinned and latest goose, documented, offered in the Pair dialog.

## What it takes

1. **Engine choice, persisted.** `galopin enroll --engine opencode|goose` (default opencode); stored in the
   machine's config; `galopin run` uses it (the `--backend acp --acp-command` flags stay for experiments).
   Re-enroll keeps it unless passed. The Pair dialog offers the engine (advanced section).
2. **Install and pin.** A pinned goose release (like `opencode-version`), installed by the install line when
   the engine is goose (official release binary, checksum recorded in the repo since upstream publishes none),
   `bump-goose.sh` like `bump-opencode.sh`.
3. **Configuration generated by galopin, never the user's:** goose runs with its own config/home under
   galopin's config dir (not `~/.config/goose`), provider = galopin's local proxy (OpenAI-compatible), models
   from enroll's discovery, keyring disabled, telemetry off, inherited provider credentials stripped.
4. **Permissions:** `GOOSE_MODE=approve` always; goose's `auto` (and any mode that skips asks) is hidden from
   Cerea's mode list and re-asserted after every mode change and on session load; every tool call reaches
   galopin as an ACP permission request; ADR 0109's words, Auto map and floor apply unchanged.
5. **Parity with opencode where the protocol allows:** diffs (galopin snapshots, ADR 0108), history replay,
   connectors over MCP http (galopin's endpoint), model selection, cost (tagging requests by session: goose
   sends no session id, so galopin tags by the session whose turn is running). Tasks list from ACP `plan`
   updates if goose emits them; compaction via goose's own mechanism if exposed over ACP, else absent and
   documented.
6. **CI:** a goose suite like `opencode.yml` (pinned + latest), running galopin's ACP backend against real
   goose with a fake/cheap model; the e2e parity specs gain a goose machine where feasible.
7. **Docs:** agent-machines reference (engine choice, what differs from opencode), README, the `cerea` skill.

Not in scope now: goose Desktop integration, shared history with Desktop (C79), `galopin launch goose`.

## Amendment 2026-11-06 (owner)

- **Shared session store:** galopin's goose keeps its own config (provider, approve mode) but uses the user's
  normal goose session store, so sessions are shared with goose Desktop and the vscode-goose extension (one
  driver at a time; turns driven outside Cerea bypass its rules and review log). `_meta.client` is set so
  galopin's sessions are visible there.
- **`galopin goose setup`:** writes a provider entry into the user's own goose config pointing goose Desktop,
  the CLI and vscode-goose at galopin's local proxy (Pystino models and billing); idempotent, `--remove`,
  refreshed by `galopin models refresh`.
